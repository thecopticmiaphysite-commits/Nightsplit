THE GAME
==================================================

NAME:

NIGHTSPLIT

I strongly prefer this name. The previous working name BREAKNIGHT was abandoned.

GENRE / CORE IDEA:

NIGHTSPLIT should become a highly replayable cooperative survival/action roguelite Roblox game.

The game should combine:

- survival
- exploration
- objectives
- escalating enemies
- cooperative teamwork
- classes
- weapons
- perks/powerups
- random loot
- dangerous strongholds
- secrets
- environmental storytelling
- mystery
- long-term progression

The game should feel easy to understand initially but have substantial depth underneath.

The biggest priority is GAMEPLAY.

I do not want a game that feels like a menu simulator or Roblox cash grab.

==================================================
THE CORE RUN
==================================================

The exact structure can evolve through playtesting, but the intended concept is:

Players enter a run.

They explore.

They complete objectives.

They earn currency/resources.

They open new sections of the world.

They acquire weapons/items.

They improve themselves with perks/powerups.

They encounter increasingly dangerous enemies.

They discover strongholds and special encounters.

They find story clues/secrets.

Night/Breaknight events increase danger.

Players make decisions about:

- where to explore
- which areas to unlock
- what to buy
- which objectives to pursue
- what equipment to keep
- whether to risk dangerous locations
- whether to rescue teammates
- whether to gamble loot
- when to retreat

The run should create stories naturally.

Example:

A teammate dies deep inside a dangerous region.

Their Echo Tag remains behind.

The team must decide whether to risk going back.

Someone retrieves it.

Now they must carry it to a dangerous reboot location.

The team barely survives.

That kind of emergent moment is EXACTLY what I want.

==================================================
DAY / NIGHT / NIGHTSPLIT SYSTEM
==================================================

There should be a changing run state.

We have already begun experimenting with:

Intermission
Day
Breaknight/Night

The terminology can be refined.

Night should meaningfully change gameplay rather than simply making the map darker.

Possible night effects:

- stronger enemies
- different enemies
- roaming threats
- special events
- reduced visibility
- dangerous environmental changes
- unique loot opportunities
- stronghold activation
- map changes
- story events

As nights increase, difficulty should escalate.

Do not simply increase enemy HP forever.

Difficulty should also evolve through:

- enemy behaviors
- combinations
- environmental pressure
- resource scarcity
- special enemies
- objectives
- map conditions

==================================================
OBJECTIVES
==================================================

Runs should contain objectives.

Basic objectives should:

- move the run forward
- encourage exploration
- provide currency/rewards
- create risk

There should eventually be multiple objective types rather than pressing one button repeatedly.

Examples could include:

- restore power
- defend an area
- retrieve an object
- repair machinery
- activate relays
- eliminate a target
- escort/carry something
- survive an event
- enter a stronghold
- recover information

Objectives can become important storytelling tools.

==================================================
CURRENCY
==================================================

Players earn currency DURING the run.

Currency should be useful for things such as:

- opening doors
- unlocking areas
- perks
- powerups
- equipment
- possibly rerolls/upgrades
- other run decisions

Currency should create meaningful tradeoffs.

Do not make it meaningless by giving players infinite amounts.

==================================================
DOORS / WORLD PROGRESSION
==================================================

I specifically want Zombies-style paid doors/area progression.

Some regions begin inaccessible.

Players spend earned run currency to open them.

Opening areas should:

- expose new enemies
- reveal objectives
- reveal loot
- provide shortcuts
- reveal story
- unlock stronger equipment
- potentially make the run more dangerous

Door prices and progression should be data-driven/configurable rather than hard-coded everywhere.

==================================================
STRONGHOLDS
==================================================

I want dangerous enemy-controlled areas inspired by the progression concept of 99 Nights.

Players enter a dangerous location.

They must defeat enemies or complete an encounter.

The reward should sometimes be essential to progressing the run or uncovering the story.

Strongholds should feel dangerous enough that entering one is a meaningful decision.

Potentially:

Exact balance can be playtested.

==================================================
DEATH / ECHO TAG REVIVAL
==================================================

This is one of my favorite mechanics.

When a player fully dies, they leave behind something like a dog tag.

Working NIGHTSPLIT name:

ECHO TAG

The Echo Tag remains where they died.

A teammate must physically retrieve it.

Then they must carry/bring it to a dangerous reboot/relay location.

Successfully doing this revives the dead teammate.

This should NOT simply be:

"Hold E next to dead player for three seconds."

I want death to create an actual rescue mission.

Potential considerations:

- retrieval danger
- limited recovery time
- carrying limitations
- reboot location danger
- enemies reacting to reboot attempts
- special reboot events
- class interactions

The system should encourage clutch cooperative moments.

==================================================
MOVEMENT
==================================================

THIS IS A VERY HIGH PRIORITY.

Movement must feel excellent before we pile hundreds of systems on top.

Target movement:

Walk
Sprint
Crouch
Slide

Potential future movement can be evaluated later.

SPRINT:

Keyboard:
LeftShift

Controller:
L3

Mobile:
dedicated button

Initial speeds we've experimented with:

WalkSpeed = 16
SprintSpeed = 24

These are not sacred values. Tune based on feel.

Sprint uses stamina.

STAMINA:

There should be a minimal stamina indicator.

Prefer a small clean bar in a bottom corner.

Stamina:

- drains while sprinting
- regenerates
- handles exhaustion cleanly
- should not flicker or behave inconsistently

CROUCH / SLIDE:

This is contextual.

Keyboard:
C and/or LeftCtrl

Controller:
B / Circle-equivalent

Mobile:
dedicated contextual movement button

Behavior:

IF NOT SPRINTING:
pressing the contextual movement button = CROUCH.

IF SPRINTING/MOVING:
pressing it = SLIDE.

Pressing crouch while sprinting must NOT simply stop the player.

That was an earlier bug.

CROUCH:

Crouch needs to be REAL.

Not merely lowering the camera.

Eventually it should include:

- visible R15 crouch animation
- lowered player stance
- appropriate movement speed
- lower camera
- physical clearance where appropriate
- inability to stand if there is insufficient headroom

SLIDE:

Slide needs real momentum.

Not just lowering the camera.

Desired feel:

Sprint -> press crouch -> player carries momentum into a smooth slide.

Slide should have:

- initial momentum
- controlled deceleration
- duration
- cooldown if necessary
- real slide animation
- clean transition back to movement
- slope behavior eventually
- no freezing

Use modern Roblox physics methods.

Avoid deprecated BodyVelocity/old BodyMovers.

Consider ApplyImpulse / LinearVelocity / appropriate modern constraints depending on implementation.

Do not recklessly manipulate physics in ways that create network/exploit problems.

==================================================
MULTIPLAYER / SECURITY
==================================================

Assume clients are untrusted.

Important gameplay should be server-authoritative.

Especially:

- damage
- currency
- purchases
- loot ownership
- objectives
- revives
- progression
- rewards
- inventory changes

Validate RemoteEvents/RemoteFunctions.

Rate-limit where appropriate.

Never trust the client saying:

"I killed this enemy."
"Give me 10,000 currency."
"I opened this chest."
"I own this item."

Client should request actions.

Server validates them.

PERFORMANCE
==================================================

This game may eventually have:

- multiple players
- many enemies
- projectiles
- loot
- events
- large environments

Design with performance in mind.

Avoid:

- unnecessary per-frame loops
- hundreds of uncontrolled connections
- excessive replication
- constantly scanning Workspace
- memory leaks
- expensive pathfinding spam
- huge monolithic scripts

Use tags/config/modules/services appropriately.
